# 发布前检查

## 内容与隐私

- 使用虚构示例或已获得明确公开许可的真实内容。
- 检查姓名、昵称、生日、纪念日、手机号、邮箱、地址、个人域名和内部链接。
- 清理照片的 EXIF/GPS 信息，并检查镜面、票据、车牌、工牌和屏幕背景。
- 检查文件名、替代文本、注释、测试夹具和构建日志中的隐私信息。
- 从干净仓库发布，避免旧 Git 历史继续暴露已删除的内容。

## 知识产权

- 确认照片中人物同意公开。
- 确认图片、字体、音频、图标和文案允许再分发。
- 不使用商业游戏的角色、精灵图、地图复刻、音乐或商标。
- 如引入第三方素材，记录作者、来源、许可证和必要的署名文本。

## 工程与供应链

- 使用受支持的 Node.js 版本执行 `npm ci`、`npm test` 和 `npm run build`。
- 审阅依赖锁文件，确认下载源是预期的公共 registry。
- 查看依赖安全告警，并在发布后启用自动更新。
- 设置分支保护，要求 CI 通过后才能合并。
- 检查 Service Worker 缓存版本；内容大改时递增缓存名。

## 产品质量

- 在桌面键盘、手机触控和横屏模式下完成一次完整通关。
- 检查色彩对比、键盘焦点、替代文本和 `prefers-reduced-motion`。
- 用至少一种窄屏设备确认终章和弹层可滚动、不截断操作按钮。
- 检查目标受众所需的语言、本地化日期与文化表达。

## 发布设置

- 补充仓库描述、主题标签、截图和演示地址；截图也必须经过隐私检查。
- 确认许可证符合你的真实意图；本模板默认 MIT。
- 启用私密安全报告、依赖告警和自动化备份。
- 若使用自定义域名，配置 HTTPS、安全响应头和最小化的访问统计。
